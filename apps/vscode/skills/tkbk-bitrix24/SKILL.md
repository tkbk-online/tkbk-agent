# Битрикс24

Используй, когда пользователь просит что-то сделать в Битрикс24: посмотреть лиды или сделки, завести лид или задачу, выгрузить воронку, написать интеграцию.

## 1. Способ доступа

Предпочтительно — MCP-сервер `tkbk-b24` (инструменты: лиды, сделки, новый лид, новая задача). Если сервера нет — предложи подключить:

```json
{
  "tkbk-b24": {
    "url": "https://mcp.tkbk.online/mcp/b24",
    "headers": {
      "Authorization": "Bearer cr_…",
      "x-b24-webhook": "https://<портал>.bitrix24.ru/rest/<id>/<код>/"
    }
  }
}
```

Локально: `npx -y github:tkbk-online/tkbk-mcp bitrix24` с переменной `BITRIX24_WEBHOOK_URL`.

Если пользователь пишет код интеграции, работай с REST напрямую: входящий вебхук вида `https://<портал>.bitrix24.ru/rest/<user_id>/<код>/<метод>.json`. Вебхук — это секрет: читай его только из переменных окружения (`BITRIX24_WEBHOOK_URL`), никогда не вставляй в код и в ответы.

## 2. Полезные методы REST

| Задача | Метод | Заметки |
|---|---|---|
| Список лидов | `crm.lead.list` | `filter`, `select`, `order`; постранично по 50, поле `next` в ответе |
| Лид по id | `crm.lead.get` | |
| Новый лид | `crm.lead.add` | `fields.TITLE`, `NAME`, `PHONE: [{VALUE, VALUE_TYPE:"WORK"}]`, `EMAIL`, `SOURCE_ID`, `COMMENTS` |
| Сделки | `crm.deal.list`, `crm.deal.get`, `crm.deal.add`, `crm.deal.update` | стадии — `crm.dealcategory.stage.list` |
| Контакты | `crm.contact.list`, `crm.contact.add` | |
| Задача | `tasks.task.add` | `fields.TITLE`, `RESPONSIBLE_ID`, `DEADLINE` (ISO 8601), `DESCRIPTION` |
| Комментарий к сделке | `crm.timeline.comment.add` | `fields.ENTITY_ID`, `ENTITY_TYPE: "deal"`, `COMMENT` |
| Пользователи | `user.get` | чтобы найти `RESPONSIBLE_ID` по имени |

Лимит Битрикс24 — около 2 запросов в секунду на портал; при `QUERY_LIMIT_EXCEEDED` подожди 1–2 с и повтори. Для массовых выборок используй `batch` (до 50 команд за вызов).

## 3. Правила

- Создание и изменение сущностей — только после подтверждения: покажи, какие поля заполнишь, и спроси «создать?».
- Из переписки в лид: телефон нормализуй к `+7XXXXXXXXXX`, в `COMMENTS` положи краткую суть запроса и ссылку/дату источника, в `SOURCE_ID` — канал (если известен), не придумывай поля, которых не было в тексте.
- Персональные данные клиентов не выводи в логи и файлы без необходимости.
- Если пользователь просит отчёт по воронке — собери сделки по стадиям, посчитай количество и сумму `OPPORTUNITY`, выведи таблицу и конверсию между соседними стадиями.
